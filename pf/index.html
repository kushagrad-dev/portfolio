CASE STUDY · 01

From a vague feature idea to a focused engineering scope.

THE PROBLEM

The goal was to scope a meal-swap suggestion feature for a hostel nutrition and macro tracker.

Users already logged meals against a personal protein target and could be short on protein by dinner. The feature needed to suggest useful items from the existing day's menu.

CONSTRAINTS
  • Use the existing structured menu data.
  • Focus primarily on closing the protein gap.
  • No external nutrition API.
  • No new recommendation or ML pipeline.
  • No new database collections.
  • Keep the first version small and implementable.
WHAT AI CHANGED

My initial prompt produced broad suggestions, including ideas such as external food APIs and machine-learning approaches.

Iterating with real project context changed the problem from "build a recommendation feature" into a much smaller ranking problem over a fixed set of existing menu items.

FINAL DIRECTION

The final scope was a simple suggestion endpoint:

GET /api/suggestions?userId=&date=

It returns the user's remaining protein gap and ranked suggestions from the remaining menu items.

EDGE CASES
  • Missing protein target.
  • Protein target already met.
  • Local date/time handling.
  • Menu items missing protein data.
KEY LESSON

The biggest improvement did not come from making the prompt longer. It came from giving AI real context, forcing the reasoning into steps, and explicitly considering edge cases.

AI helped explore and challenge the solution. I retained the final scope and engineering decision.
